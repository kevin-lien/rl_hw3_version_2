Vectorized Environments are used to stack multiple independent environments into a 
single environment. 
•
Training the agent on a parallel environment helps speed up the training process. 
•
You can use VecEnv for training and still use the original Env for evaluation. 
•
Example: SubprocVecEnv can create separate envs that agents interact with in parallel. 
•
Note: VecEnv wraps the environment with Gym 0.21 API logic, so: 
•
Output of VecEnv.step() would be obs, reward, done, info instead. 
•
Output of VecEnv.reset() would be obs only. 
(See VecEnv API vs Gym API)

You can modify the training code to let agent explore other actions even after 
illegal moves.

• 1v1 space duel: destroy the enemy ship, then finish off its pilot.  
• Rules:  
• Win: Shoot ship -> astronaut ejects -> kill the astronaut 
(With bullet/laser)                                  (With bullet/laser/ramming) 
• Time limit: 1500 steps (~30 s). If both players are still alive, it's a draw.  
• Ammo: a 3-bullet magazine, refilled at 1 bullet/50 steps (~1 s) 
• Lasers: Destroy asteroid -> laser drop (50%). One-shot, instant beam. 
• Astronaut: can't shoot, only fly and dodge. Survive 200 steps (~4 s) -> new ship. 
• Obstacles: the planet and the cover walls block both ships and shots.  
• Spawn: random each game, mirrored across the planet, at least 500 px apart. 
• Notes: 
• The map is 1200x800 pixels 
• Center is at (600, 400) 
• A lot of states are defined in pixel units (position, speed… )
